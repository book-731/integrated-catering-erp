# v0.4.0 單店 ERP 決策（2026-11-12）

依使用者最新授權，由主導者透過 Codex 完成整合，再由五位組員修改。沿用 v0.3.0，不拆成六套應用；Windows 本機是驗收目標，Docker／Linux 選用。正式簡報、功能圖及 ERD 仍未提供，未假稱閱讀。

## 保守預設

1. 單店、TWD，金額 Decimal(12,2)、數量 Decimal(14,3)，API 固定金額二位／數量三位字串。整數只用於份數、選項上下限、版本與計數。報表金額以 Decimal 四捨五入；圖表寬度才轉 Number。
2. 套餐為固定一般餐點組件與套餐獨立售價，不允許巢狀套餐。套餐自己的基本配方也會耗用。組件的客製選項不自動套用，需設於套餐上。加購／選項為非負價差與額外食材，可設定群組最少／最多選取數；辣度等無耗材選項可無配方。不提供負用量替換或自動單位換算。
3. 下單保存單價、名稱、分類、選項、組件及食材 SKU／名稱／單位／每份用量／整列總需求快照。改價、改配方不改歷史；明細建立後不可編輯，輸入錯誤的待處理單先取消重建。
4. PENDING → PREPARING 扣庫，不預留。逐食材彙總快照，庫存、流水、狀態與冪等結果同一交易；不足整筆回滾。PREPARING → COMPLETED 前須全額付款紀錄。PENDING／PREPARING 可由櫃檯或管理者取消；廚房只可開始／完成。
5. 製作後取消不自動回庫，避免食物已製作卻變回原料。可回收原料由管理者以有原因的 COMPENSATION 流水補回。已付款單禁止直接取消，本版沒有退款、分次付款、真實金流或會計功能。
6. 折扣與服務費是明確金額；折扣不得高於小計，無額外稅額。小計由伺服器計算，不接受前端總額。外送只存備註，不串平台；付款方式只記錄 CASH／CARD_RECORD／TRANSFER_RECORD。
7. OPENING 僅允許無流水食材一次設定；COUNT 填實際盤點總量，其餘填正異動量。所有變動記 signed quantity、before／after、單位、原因、actor、來源及時間；沒有裸改庫存 API。遷移前非零庫存自動留 migration 基準，不改原量。
8. 同一單店的所有目錄／業務寫入共用 PostgreSQL advisory transaction lock 12002002，並鎖／重驗操作者。這是低流量課程展示的保守取捨，不宣稱大型連鎖店吞吐量。任一程序的併發都由 DB 協調；沒有僅記憶體去重。
9. 每個新寫入帶 UUID requestKey，唯一範圍為操作者＋key。交易保存正規化 payload hash、scope 與結果；同 key 同內容重播，不同內容 409。前端未改內容的失敗重試沿用 key，改內容產生新 key。沒有任意清除命令憑證的 API。
10. 採購 REQUESTED → APPROVED → ORDERED → PARTIAL／RECEIVED，支援部分收貨，拒絕超收；每次收貨有獨立紀錄並同交易入庫。未收貨前可取消，已收貨採購不直接取消。申請建立後明細不編輯，錯誤申請取消重建；本版不做退貨或採購付款。
11. 職務及員工獨立於登入帳號，由 ADMIN／MANAGER 管理。班表採 [開始,結束) 半開區間，允許相鄰班次，拒絕重疊及核准請假衝突。先停用衝突班次再核准請假。出勤由管理者登錄／補登，拒絕重疊與多筆未下班，未下班不算已完成出勤時數。無薪資、勞保、報稅或法律合規引擎。
12. 台北時區、午夜營業日，報表依 completedAt 計入 COMPLETED；取消／未完成不計營業額。指定1–366日，可查一天／一月。分類依訂單快照，分類營收按該分類明細小計占整單小計比例分攤折扣／服務費，逐單四捨五入至分；零額單分攤零。熱銷 amount 為折扣前明細小計，與淨營業額不同。分類只篩銷售指標，庫存／採購／人事仍依日期統計。
13. 基本食材足夠性查詢包含固定套餐組件，不含尚未選定的客製／加購；前端明示估算限制。實際製作一定依訂單完整選項快照檢查。

| ---------------------------- | ----- | ------- | -------- | -------------------- |
| 帳號管理                     | 管理  | 無      | 無       | 無                   |
| 食材／菜單／套餐／配方       | 管理  | 管理    | 菜單唯讀 | 菜單／配方／庫存唯讀 |

## 供團隊後續確認

正式課程需求、套餐自選規則、折扣／服務費、製作後取消、營業日與出勤修正稽核政策。上述已有可操作預設，不因一般歧義停止開發；若改成多店、負庫存、退款或公開部署，需先重新設計與驗證。排除真實金流、總帳、硬體、報稅與 AI 預測。
